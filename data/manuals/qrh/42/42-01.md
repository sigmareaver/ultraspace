# 42-01 — DATA BUS A FAILED

**Entry condition:** `DATA BUS A FAILED` annunciated (warning). No terminal on
DB-A is answering the controller.

**What this is not:** a repair. This page buys you a correct picture of the
ship in under a minute and hands you to FIM 42-11 §3, which finds the terminal
doing it. Do not start cycling breakers from here.

## 1. Stop the panel from being useless

```
 1. Annunciator panel ...................... ACK
```

First action, every time (00-00 §2). The lamps stay lit; the masters go steady;
the panel regains the ability to tell you about the next thing. You are about
to spend several minutes with your attention inside one system, which is
exactly when a second casualty arrives.

## 2. Is the controller alive?

```
 2. DB-A bus table ......................... READ
       "ON AIR" ........................... continue
       "NO DATA" .......................... this is not your page
```

A failed *bus* and a dark *controller* produce the same silence at the panel
and completely different work. If the table reads NO DATA the controller has
no power and there is nothing wrong with the bus at all: go to SOM 42-00-00 §6
and find the breaker. Do not troubleshoot a bus you cannot see.

## 3. The readings you have just lost

```
 3. Wait ................................... 2 s
 4. Instrument panel ....................... READ, mark every ? STALE line
       those values are frozen. The loads are not.
```

This is the part crews get wrong. Every instrument carried by a terminal on
this bus has stopped being refreshed, and each one is still showing its last
honest number — a true reading about a moment that has passed (SOM 42-00-00
§8). The equipment those instruments watch is completely unaffected: a cabin
load with a frozen ammeter is still drawing exactly what it was drawing.

**Disregard every stale line for the duration.** If you need one of those
values, get it from a panel-wired instrument or from the equipment itself.
The one thing you must not do is make a decision — shed a load, close a tie,
declare a system healthy — on a number that stopped moving four minutes ago.

## 4. What caused it, for the log and not for now

```
 5. Particle flux .......................... READ and NOTE the value
```

Takes three seconds and changes nothing you are about to do — which is why it
is here rather than in the FIM task, where you will have forgotten. A bus
that failed at four figures of flux failed because of the weather; the same
failure at background rate says something about the hardware (FIM 42-11 §4).
The bus table cannot tell these apart and the flux will have moved by the time
anyone asks.

## 5. Hand off

```
 6. FIM 42-11 §3 ........................... THE JAM
```

Every terminal dark, declared within tenths of a second of each other, is the
babbling-terminal signature. FIM 42-11 §3 cycles the feeds in order and the
bus recovers the moment the guilty terminal goes dark.

If the ship is inside a particle event (SEU HAZARD lit), read SOM 42-30-02
first: restoring a terminal into a high flux is how you get to do all of this
again in a few minutes.
