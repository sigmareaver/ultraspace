# 42-30-01 — Data Bus Checkout

**From:** buses powered (SOM 24-30-01 or 24-30-03).
**To:** DB-A HEALTHY, RT 5 and RT 12 answering, error counters zeroed and
staying zero.

NOTE 1: Close the terminal feeds **before** the controller feed. If the
controller comes on line first it will declare the dark terminals FAILED,
and DATA BUS A DEGRADED will raise and then clear as they answer
(42-00-00 §7). The error counters will show the lapse until somebody zeroes
them. Do it in order and there is nothing to explain.

NOTE 2: **Read the counters before you zero them.** The totals are the only
record the ship keeps of how the bus has behaved, they never rewind on their
own, and step 5 discards them for good. A count you did not read is a question
you answered by erasing it. Zero at checkout and after maintenance — not when
a number looks inconvenient.

## Procedure

Execute per checklist `som-42-30-01`:

```
 1. CB A2 (RT 12 feed) ..................... CLOSE
 2. CB E3 (RT 5 feed) ...................... CLOSE
 3. CB E2 (bus controller feed) ............ CLOSE
       DB-A health ......................... 1.0 within 2 s
 4. DB-A bus table ......................... READ
       RT 5, RT 12 ......................... OK
 5. DB-A error counters .................... ZERO --confirm   (NOTE 2)
 6. Run the bus ............................ 2 s
 7. DB-A bus table ......................... READ
       TOTAL ............................... 0 errors
```

Step 3's indication is the controller's published health: 1.0 means every
scheduled terminal answered. If the health does not reach 1.0, stop here —
the table in step 4 names the suspect, and further isolation is FIM
territory, not checkout (FIM 42-11).

Steps 5 to 7 are what makes this a checkout rather than a glance. The totals
are monotone: a bus that had one bad afternoon carries that count for the rest
of the flight, so "errors 0" means nothing until the counters have been zeroed
and then given something to count. Two seconds is twenty polls per terminal —
short, but a terminal that is going to miss usually misses inside that.

If step 7 reads anything but 0, you have an *intermittent*, which is a worse
problem than a dead terminal and a better one to find here than in a burn. Note
the count and the terminal, and do not zero it again to make it go away.

If the bus table reads NO DATA, the controller itself has no feed: verify
CB E2 and BUS E before anything else (42-00-00 §6). Do not troubleshoot a
bus you cannot see.
